### 关键技术结论（避免以后重复踩）

1. **子集覆盖校验要排除控制字符**：U+000A 无字形，会让断言误报缺字。已在
   `collect_chars()` 里用 `unicodedata.category(c) != "Cc"` 过滤。
2. **可变轴收窄是死路**：`instantiateVariableFont` 先于 subset 会触发 fontTools
   的 `KeyError: 'uniFF5C'`；反序可行但只省 2.5 KB（0.6%），已放弃。
3. **`.ripple-char` 的 reduced-motion 段确为死代码**：`initRippleText()` 在
   prefers-reduced-motion 下直接 return，`.ripple-char` 永不被创建。注意理由不是
   「被全局块覆盖」—— 全局块只改 animation/transition-duration，不碰 transform。
4. **`a { transition: 0.3s ease }` 是隐式 all**，且时间值位置写错。`a` 上真正会变的
   只有 color 与 opacity（`#globalnav` 未激活项 0.15→1、`.detail_foot a:hover` 0.6），
   已改显式列出。
5. **首页开屏动画会污染截图**：`<html>` 初始带 `.is-loading`，headless 的
   virtual-time 不推进它 → 首屏拍成空白。COMPACT 里还原终态即可；注意
   `.name_en span` 的终态是 `opacity: var(--latin-ghost)`（0.05 的背景水印），不是 1，
   写成 1 会拍出全黑假象。
6. **桌面端不需要 iframe**；`frame` 模式只用于移动端（Chrome on Windows 把
   headless 窗口宽度钳到约 500px）。
7. 首页 `.design` 区块内**没有 `<a>`**，projects 页走 `design_index` 且其
   `a::before` 本就 `content:none` —— 所以删 `#main_contents .design a::before` 是安全的。

**用户决策**（AskUserQuestion）：公开仓库 / 仓库名 `personal-website` / 推完整源码（含 tools、文档、记忆日志）。

**网络真相 —— 之前「GitHub 不通」的判断是错的**

- 本机有 HTTP 代理 `http_proxy=http://127.0.0.1:12010`（还有 `CODEBUDDY_SERVICE_PROXY_URL=http://127.0.0.1:12209/...`）。
- `curl https://github.com` → 200（首次 17.8 s，之后 1.6 s）；`api.github.com` → 200。
- **git 协议完全可用**：`git ls-remote https://github.com/octocat/Hello-World.git` 成功返回 `7fd1a60b`，耗时约 14 s。
- 早期 `curl` 得到 `000` 是代理未就绪/首次连接超时所致，**不是网络被墙**。
- 教训：本机 git 操作必须带着 `http_proxy` 环境变量跑，且要留足超时（≥60 s），不能用默认短超时下结论。

**两个硬阻塞**

1. **GitHub 连接器权限不足**：`create_repository` → `403 Resource not accessible by integration`。该连接器是 GitHub App 形态，授权里没有建仓权限。连接器本身 `bound: true, enabled: true`，读操作（`get_me` 等）正常。
2. **MCP 无法推二进制**：读 `github-mcp-server` 源码 `pkg/github/repositories.go:1643` 的 `PushFiles`，它把内容塞进 `github.TreeEntry{Type:"blob", Content: new(content)}`，**纯 UTF-8 字符串，无 base64 通道**；`create_or_update_file` 的描述也明说「Do not base64-encode it; this server does that」。本仓库 16 个二进制（13 JPG + 2 woff2 + font-src，合计 1.78 MB）走 MCP 必被写坏。

**结论**：GitHub 部署必须走原生 `git push`，且需要一个能建仓 + 能写内容的凭据。用户已选择「提供 GitHub Token」路线。
